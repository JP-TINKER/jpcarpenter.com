# Cross-framework routing (small SaaS)

One operational spine. Many examinations. You do not run four separate companies.

## If / then

| If | Then | Do not |
|----|------|--------|
| A customer asked for a **SOC 2 report** | Name the Trust Services Criteria in the letter (often Security-only). Type 1 = design as of a date. Type 2 = design + operating effectiveness over a period. A CPA issues the report. | Call yourself “SOC 2 certified.” |
| No customer ask yet — need an ops spine **this week** | Use NIST CSF 2.0 language (Govern → Recover) as the free spine. Fill risk + control map tabs. | Buy ISO 27001 just to look busy. Treat CSF as a substitute for a SOC 2 report. |
| You **ship AI features**, get AI questionnaires, or put customer data in prompts | Start the planned **42001 Readiness Lite** pack (ten files). Use NIST AI RMF as a voluntary spine. | Claim “ISO 42001 certified.” ISO does not certify organizations. |
| Card data or payments run **as a service** for customers | Treat as a PCI **service provider** scoping question (SAQ D for Service Providers territory). Get QSA/counsel. | Hand yourself a merchant SAQ as if you were a shop. |
| You want **policy boilerplate** | Customize FOSS starters carefully — or keep using the short policy starters under Resources. | Paste a GitHub policy pack into the auditor portal unchanged. |

## One sentence for stakeholders

> This pack tells us which program to run this quarter and gives us tabs to track it. It is not a SOC 2 report and it is not an ISO certificate.

- **42001 lite (B):** only when AI is in the product or vendor path — planned free product on jpcarpenter.com.
